## T08 — 自由飞行目标锁定、自动减速与天体防穿越

> 任务：T08 / P1  
> 日期：2026-10-20  
> 范围：太阳系自由漫游，包含太阳、八大行星和七颗已建模卫星  
> 状态：已实施代码；浏览器交互、连续飞行及移动端待验收

### 1. 背景与目标

原自由漫游支持 W/A/S/D、Space、Shift 与四档飞行速度。位置直接按固定步长变化，释放按键即停止；只有八大行星中的非太阳天体做过简单的终点位置修正。独立的目标锁定、自动接近减速与太阳/卫星防穿越尚未实现。

目标是让用户选择任意已支持天体作为航行目标，不进入行星近景模式也能自动靠近；距离目标越近速度越低，在安全距离附近停靠，并继续跟随目标的公转。手动输入要能立即接管，解除锁定后恢复普通自由漫游。

### 2. 方案与已实施内容

1. **导航入口**：复用底部天体导航区域。自由漫游时改为“航行导航”，显示包含全部 16 个天体的下拉选择、飞往/停止与解锁按钮；搜索结果和画面中的天体点击，在自由模式下改为锁定目标。手机端仍通过底部“航行”按钮展开，飞行期间保留可见的“停止航行”快捷按钮。
2. **锁定状态**：在 UniverseApp 中独立保存 freeTargetId、freeAutopilot、freeArrived、freeFollowing 和三维速度，明确与行星近景 focusId 区分。锁定时相机逐渐朝向运动中的目标；离开自由模式会清理锁定与动量。
3. **自动接近与平滑制动**：以飞行速度档位确定最高速度；依据到安全停靠距离的余量，通过近似制动距离关系控制目标速度，再以指数阻尼调整实际速度。单帧运动限制在剩余距离以内，防止高倍速或帧率下降时越过停靠点。抵达后保持相机相对于目标的位置偏移并跟随天体移动。
4. **手动接管**：自动航行过程中按移动键即退出自动航行，保持目标锁定；释放按键时速度逐渐衰减。锁定下按 W 接近目标也受安全速度限制；S、横向及升降方向仍可用于绕行。Esc 先停止自动航行，再解除目标锁定。
5. **天体防穿越**：新增 src/core/freeFlightPhysics.js，使用全运动线段与球形安全边界求交，覆盖太阳、八大行星与七颗卫星。镜头拖拽、滚轮缩放和按钮缩放在 OrbitControls 更新后再次约束；自动航路撞上遮挡天体时安全停止并提示用户手动绕行。
6. **响应式与说明**：手机使用既有折叠式底部导航，不增设常驻全屏面板。同步更新页面探索指南、搜索提示和 README 操作说明。

## T11 — 天体参数对比数据口径统一

> 任务：T11 / P1

## T12 — 天体遮挡阴影、大气边缘与木星云带动画

> 任务：T12 / P2 视觉增强  
> 日期：2026-10-20  
> 状态：增强代码及画质策略已完成、生产构建通过；WebGL Shader 视觉、手机/桌面性能和遮挡相位待验收

### 1. 背景与目标

现有太阳点光源、行星表面明暗、地球夜侧灯光、大气边缘辉光和木星贴图均可使用，但没有明确的球形天体之间的遮挡投影逻辑。大气偏简单 Fresnel 边缘效果，木星纹理仅随整颗行星自转。

目标是增加低成本、可在低画质中关闭的视觉增强：月球与其他卫星/行星遮挡阳光时产生柔和阴影；大气晨昏线呈现更丰富的边缘颜色；木星云带在贴图上缓慢形变。场景仍然是科普展示比例，不要求精确食预测或大气光学模拟。

### 2. 开发方案与实现

1. **球形遮挡投影**：新增 `src/universe/celestialLighting.js`。在已有 `MeshStandardMaterial` 的直接受光阶段，利用片元世界坐标到太阳的方向，计算一到两个球形遮挡体与阳光射线的近似交叠，降低太阳直接漫反射/高光贡献；保留环境光和地球夜侧城市灯光。柔和边缘用于模拟有限太阳视盘的示意半影，没有创建 ShadowMap 或额外阴影相机。
2. **遮挡体筛选**：为太阳以外的行星及卫星维护复用的世界坐标缓存，根据目标到太阳的方向筛选可能遮挡阳光的球体。自动/中画质每约四帧最多选一个，高画质每约两帧最多两个；低画质不运行该 CPU 筛选。银河初始页的太阳系不可见时，也跳过额外筛选。
3. **大气散射近似**：扩展既有 `createAtmosphereMaterial()`，保留背面绘制和无深度写入；自动/高画质加入晨昏线暖色、角度相关的大气边缘与朝太阳方向的增强散射，低画质沿用原有简单大气光晕。用于地球、金星、天王星、海王星及土卫六。
4. **木星云带运动**：在木星原有 JPG/程序纹理材质上修改贴图 UV 采样，沿纬度叠加缓慢剪切与微小波纹。只更新 Shader 时间 Uniform，保持原贴图与加载回退，不重新生成或上传整张纹理；暂停模拟时间则停止云带变化。低画质将强度设为零。
5. **原有材质共存**：新增 Shader Hook 链接在既有地球夜侧发光处理之后；对地球表面与透明云层均应用球体阴影，保持旧法线/粗糙度、KTX2/JPG 调度、卫星射线交互和画质预设。

## T14 — 日期定位时间轴与模拟时间同步

> 任务：T14 / P1 日期定位及交互设计差距  
> 日期：2026-10-20  
> 状态：代码完成、Vite 构建与 JS 静态检查通过；桌面/手机日期拖动、近景跟随与长时间运行待设备验收

### 1. 问题和目标

旧版底部“时间控制”只有暂停/继续、0～50× 倍速滑杆和持续递增的“演示时间”文字，没有独立的指定日期入口。用户无法拖动到任意演示日期，也无法在暂停状态下观察不同时刻的太阳系相位。旧的天体自转还采用逐帧累加角度，需要改为绝对模拟时刻取值才能准确支持反向拖动。

本次为底部增加独立的**日期轴与原有倍速滑块**，让日期跳转、轨道位置、天体自转、暂停、倍速及近景镜头使用同一个演示时间。

### 2. 设计与实现

1. **底部日期轴**：在 index.html 的时间控制模块增加 timeline-range 滑块和 timeline-date 原生日历输入。提供日期定位文字、起止年份及“演示轨道 · 非真实历表”标识。桌面独立占一行，手机将模块调整为带有第二行日期控制的网格，保留较大的时间和导航按钮触控区。底部和抽屉位置沿用已有视口测量自动调整。
2. **窗口与日历**：用 2026-01-01（UTC）作为现有模拟时间的演示纪元。日期轴一次显示约 20 年；输入一个窗口以外的新日期时，自动以该日期为中心重置可见区间。精确日历输入限制 1900-01-01～2300-12-31，日期运算用 UTC 避免用户时区造成 ±1 日误差。
3. **时间与轨道**：src/universe/createSolarSystem.js 新增 setSimulationDays(days)：输入相对于纪元的演示天数，转换为原模拟秒数 days / 5，立即以零步长重新计算太阳、八行星和十三颗卫星的位置、程序化云带时间。太阳、行星/卫星、地球云层、小行星带与日冕自转由每帧增量改为使用绝对模拟时间计算，确保同一日期反复跳转画面一致，且能正确反向拖动。
4. **相机与目标跟随**：UniverseApp.seekSimulationDays(days) 保留当前聚焦天体的相机相对偏移；在动态焦点飞行过程中同步平移飞行起点/中点和观察目标。自由飞行已锁定目标且正在自动靠近或跟随时，视角连同目标跳转，防止下帧重复应用公转位移；对跳转后的镜头执行场景碰撞距离检查，若与其他天体重叠则安全停止自动航行。
5. **暂停与倍速**：滑杆按下或键盘方向键操作期间设置 timelineScrubbing，仅暂时冻结演示时间增量；松开后按原有 paused 和 timeScale 继续运行。日期选择本身不修改暂停开关及倍率。每约 10 帧同步日期轴和文本，日期变化时再更新原生日历文字，避免每帧重复赋值或干扰正在输入的日期。
6. **说明/诊断**：公开 README 增加日期轴、日历操作与非真实历表声明。与原 getSimulationDays() 和性能诊断共用数据，未增加外部天文历表请求或第三方日期库。

- **手机短横屏**（例如 844×390）不使用当前横贯大半画面的底部双行控制卡，改用短顶栏与右侧小操作组，详细信息以可收起的窄侧面板呈现，避免压掉中央横向星球画面。

#### 3.0.4 视觉和响应式规则

- 宽屏桌面使用左场景轨道、右上下文抽屉与底部时间胶囊；中等平板使用紧凑顶栏和按需侧栏；手机竖屏使用单行上下工具和底部工作抽屉；低高度横屏改为右侧工具簇。按宽、高和方向共同决定布局。
- 用 8px 间距体系组织面板、统一按钮和分组方式；触控目标不小于 44×44px；只在实际展开的面板使用半透明背景，避免在 3D 主画面上铺设过多滤镜。
- 设计目标是默认至少保留约 65% 的桌面水平观测空间，手机竖屏尽量保持约 75% 的高度用于场景。这是**待实测的目标**，不以纯粹折叠数量来判定设计完成。
- 原有侧边装饰英文、银河统计和版权小字移入关于/帮助；留在画面的信息以“当前场景/选中目标 > 操作安全 > 次要状态”为优先级。
- 纯净与全屏沿用以下章节既有要求；重新布局必须保证搜索、快捷键、读屏、WebGL 恢复和自动航行紧急停止不丢失。

**A. 默认：精简探索（Compact Explore）**

- 桌面固定的是**左侧窄场景轨道 + 右上角全局按钮 + 底部短时间胶囊**，不保留缩小版的全宽顶栏或原底部大面板的框架。
- 银河首页只显示简短引导和进入太阳系入口，长篇介绍与统计按需打开。进入太阳系或交互后轻量引导可收起。
- 太阳系以天体和轨道为主，天体目录在左侧轨道；聚焦星球后以边缘“当前目标”信息签代替旧大资料卡，不自动展开长篇科普。
- 右侧视角放大/缩小/复位合并为一个可展开工具簇，画质、FPS、帮助、轨道/标签设置按用途进入设置或对应工作区。
- 手机同样保留功能，但使用单行顶栏 + 单行底栏 + 底部工作抽屉；短横屏采用侧边快捷操作。空间位置以 **3.0 节布局蓝图** 为准。

**B. 按需展开：互斥功能抽屉（Drawers）**

- “天体导航”：桌面从左侧轨道向内打开纵向目录（宽约 260～300px）；移动端从底部打开工作抽屉。选择天体后可自动合上，避免列表持续挡住画面。
- “时间控制”：常驻区只保留播放、日期与速度摘要；完整 T14 日期轴、倍率和日历从桌面时间入口或手机底部工作抽屉打开。
- “天体资料”：桌面默认只出现“地球 · 详情”入口，用户打开后才从右侧展出宽约 320～360px、最大高约 70vh 的资料抽屉；手机复用统一底部抽屉。
- “自由航行”：目标选择、速度、自动接近及解锁放入航行抽屉；正在自动航行时始终保留简明状态与紧急停止入口，短横屏仍以目标可见为先。
- 同时最多展开一个主要抽屉。打开搜索、帮助、对比等模态框时暂停其他浮层的键盘可达性，关闭后恢复焦点和原页面状态。

**C. 纯净观赏：Pure View**

- 纯净观赏时收起搜索/设置、底部时间栏、天体列表、资料工作区、大型介绍内容，以及左下当前场景/天体提示；**COSMOS 品牌、天体名称和银河标记继续显示**。原有标签显隐设置保持有效；用户仍可旋转、缩放和观察动态轨道。
- 桌面支持快捷键 `H` 切换“纯净/精简”，`Esc` 在没有更高优先级的弹窗/全屏操作时退出纯净；遵守浏览器对全屏 Esc 退出的原生行为。
- 移动端保留可发现的顶部极简退出热点（触控面积至少 44×44px，视觉低对比度）；也可轻触空白区域唤醒暂时性的退出浮层。拖动/双指手势不触发意外退出。
- 纯净状态不自动停止模拟时间、不清空天体选择、不改变画质/标签原始偏好。退出时恢复之前的浏览场景和必要的操作入口；切换时可轻柔将近景天体移到画面中心。
- 图形设备中断/恢复提示仍强制显示；自动航行进行中保留一个紧凑且可随时操作的“停止”入口，避免为了画面纯净而丢失安全控制。
- 纯净模式自身不强制申请浏览器全屏，用户可单独选择全屏或再按需组合使用。

**D. 真实浏览器全屏：Fullscreen Mode（T15 必做）**

- 增加独立的“全屏 / 退出全屏”按钮（桌面顶部工具区、移动端更多菜单）；桌面 `F` 快捷键可切换全屏，`H` 快捷键只负责纯净界面。两个模式分别保留状态，可同时开启。
- **全屏与纯净共四种组合**：

  | 组合 | 展示效果 |
  | --- | --- |
  | 普通窗口 + 精简 | 浏览器窗口内显示精简工具条与可展开面板 |
  | 全屏 + 精简 | 浏览器进入真实全屏，但仍可操作精简工具条与抽屉 |
  | 普通窗口 + 纯净 | 浏览器仍保留地址栏，网页中的 UI 几乎全部隐藏 |
  | 全屏 + 纯净 | 浏览器全屏并隐藏大多数页面浮层，优先用于沉浸观赏与展示 |

- 用户点击/按键触发时才调用 `#app.requestFullscreen()`；退出通过 `document.exitFullscreen()`。以 `document.fullscreenElement` 和 `fullscreenchange` 为实际状态依据，`fullscreenerror` 或 Promise 拒绝时恢复按钮状态并显示明确提示。不得静默假装进入全屏，也不得在页面首次打开时自动申请。
- 全屏时通过 `:fullscreen` 及当前 UI 模式设置根布局，兼容安全区；`fullscreenchange` 及原有 resize/visualViewport 链路通知 Three.js 更新 renderer/composer 尺寸、摄像机宽高比、镜头安全区域、标签避让和抽屉高度，避免拉伸、裁切或跳镜头。**全屏切换不重建 WebGL 场景、材质或纹理**。
- 纯净 + 全屏时保留低干扰的“退出纯净”“退出全屏”入口，移动端点击区域不小于 44×44px；自动航行时保留停止入口，WebGL 故障遮罩优先于纯净/全屏样式。
- `Esc` 的逻辑顺序需适配现有弹窗处理：先关闭当前弹窗；浏览器可消费 Esc 并退出原生全屏，界面必须根据 `fullscreenchange` 同步，避免同一次操作顺带退出纯净或触发“返回太阳系”。离开全屏后是否仍在纯净界面由独立 `uiMode` 决定，用户可再按 `H` 或“退出纯净”返回操作界面。
- 运行环境判定 `document.fullscreenEnabled` 与 `requestFullscreen` 是否可用；某些 iOS Safari / 微信内嵌浏览器 / iframe 可能禁止普通网页元素进入真实全屏。不可用时保持纯净模式可用，给出“当前浏览器不支持网页全屏，可使用纯净观赏模式”的提示。**不要将 CSS 全屏覆盖或浏览器 F11 伪称为成功调用 Fullscreen API**，也不强制锁定屏幕方向。

### 4. 状态与代码结构方案

新增一个由 `src/main.js` 集中管理的 UI 状态，而不是为每个组件分别叠加独立开关：

- `uiMode = compact | pure`：控制常驻 UI 层是否可见。完整操作属于 compact 模式下按需打开的抽屉。
- `isFullscreen` 不直接写死为独立真值，而是从 `document.fullscreenElement === app` 派生；`fullscreenchange` 统一刷新按钮文字、`aria-pressed`/`aria-label` 与 `#app[data-fullscreen]`。全屏和 `uiMode` 相互独立，组合模式只影响 CSS 可见性。
- `activeDrawer = none | scene | objects | time | detail | flight | settings`：对应实际工作区类型；桌面左侧目录和右侧大资料不同时展开，手机共用一个底部工作抽屉。场景快捷入口无需打开抽屉；搜索/对比仍走已有 modal 管理。
- 记住 `lastDrawer` 与进入 pure 前的焦点入口，退出 pure 后先回精简态，再按需恢复抽屉（移动端优先精简）。
- 使用 `#app[data-ui-mode]`、`#app[data-active-drawer]` 驱动 CSS，可复用 `data-view`、`data-sheet`、`data-dock` 与已有响应式断点；隐藏面板需同步 `inert`、`aria-hidden`、`aria-expanded`。
- `UniverseApp.getSceneSafeRect()`、`reframeFocusedBody()`、`updateLabels()` 识别当前**真实可见**的面板尺寸；纯净态可用画面中心，抽屉展开时为天体预留可见区域。切换 UI 不重建 Three.js 场景、纹理、相机或模拟时钟。
- 动画优先 CSS 的 opacity/transform，150～250ms 渐变；尊重 `prefers-reduced-motion`，移动端尽量降低大面积 backdrop-filter 成本。
- **组件责任重分配**：`index.html` 建立场景轨道、全局操作、上下文信息、底部时间胶囊及抽屉工作区；实施时可新建 `src/ui/layoutController.js` 和 `src/layout.css`。沿用既有业务数据和 DOM ID，避免重复功能按钮、状态竞态或整套场景重建。

### 6. 验收标准

- 1707×842 与 1366×768 桌面：**必须体现空间重排**，能区分左场景轨道、右侧按需资料、底部短时间条；不再保留跨屏幕顶部条及九颗星球整排大卡片，底部胶囊高度不超过约 56px。银河介绍不再默认遮挡主画面；纯净态大型面板全部隐藏。
- 在银河、太阳系、天体近景、自由航行的实际截图中，默认中央约 65% 宽度尽量用于观测；资料抽屉打开时镜头避让，关闭后恢复合理构图，当前星球不能被窗口或资料裁切。
- 390×844、360×740 竖屏：顶部/底部各一行，默认不同时展示长日期轴和资料大卡；手机短横屏 844×390 用紧凑顶栏与边缘快捷组，不再让底部常驻控制盖住约三分之一画面。主要触控热区至少 44×44px，遵守 safe-area-inset。
- 在银河 → 太阳系 → 地球/月球 → 土星/土卫二 → 自由漫游之间切换，能随时进入/退出纯净态。当前天体、暂停状态、日期、倍速、镜头距离和画质不意外丢失。
- 进入纯净态仍可鼠标旋转/缩放、双指缩放；截图中不应出现大型介绍区、底部操作栏、展开面板或左下场景信息/编号，但**品牌与已启用的星球名称/银河标记必须继续显示**；手机能够直接找到退出方式。
- 在支持 Fullscreen API 的桌面浏览器测试全屏四种组合：鼠标点击“全屏”和 `F` 均能进入/退出真正的浏览器全屏；`H` 切换纯净不自动退出全屏；Esc 先由浏览器退出全屏，避免意外关闭纯净或跳回其他场景。
- 全屏进出时场景宽高比、WebGL 绘制区、相机跟随与 GUI 抽屉位置同步变化，天体、暂停/倍速、日期轴、当前画质及相机视角不意外丢失；无新增重复 canvas 或渲染循环。
- 手机浏览器分别验证全屏可用与不可用两类环境；不可用时清楚提示并提供纯净模式，退出热点始终可见、可点击，安全区及横竖屏布局正常。
- 自动航行中可迅速停止；WebGL 中断提示始终可见。Esc 与已实现的搜索/帮助/比较弹窗交互顺序合理；隐藏元素不能获得 Tab 焦点。
- 对照第 0 阶段基线，普通交互和纯净模式不引入额外 GPU 场景实例或重复渲染循环；桌面与手机 FPS、纹理数量记录实际数据，发现明显下降需修复或回退效果。

### 7. 风险、兼容与回退

- 直接用 display:none 隐藏底部元素可能影响 `getSceneSafeRect()`、手机资料抽屉的 `--mobile-footer-height` 与镜头构图；先统一 UI 状态，再修改计算逻辑。
- 强行把现有大面板挪出 DOM 可能破坏既有事件监听、详情更新、ARIA 和 GSAP 过渡；首版优先保留原有 DOM ID 与事件源，逐步改变外层布局及显隐。
- 桌面场景轨道和手机场景菜单必须使用同一份场景状态，不能各建独立导航控制器；其视觉表达各自适配，不新增重复业务逻辑和事件监听。完整布局应由场景信息配置和 UI 状态驱动，不能只继续堆积 CSS 媒体查询来修补旧版。
- pure 态隐藏所有按钮会让手机用户无法退出或让自动航行失去急停入口；需按上述保留低干扰退出和安全控制。
- Fullscreen API 需要用户手势且依赖浏览器权限与支持情况；某些手机/嵌入式环境会拒绝全屏。使用特性检测与错误回退，监听浏览器原生全屏退出，避免 UI 图标停留在错误状态。触发全屏变化时及时重算画布尺寸与镜头安全区。
- 上下文恢复、错误提示和焦点回退必须高于纯净模式视觉层级。状态切换失败应能够退回原精简界面；既有 T01～T14 修改尚未提交，实施前记录 Git 状态并避免覆盖。
- 不改变星系画质、星球真实贴图或天文计算逻辑；本次目标集中于 UI 可见性和布局。
