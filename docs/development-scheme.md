# COSMOS ATLAS · 开发方案与技术设计

> 2026-10-21 起，此文件维护设计与架构。当前进度唯一来源为 [任务台账](development-plan.md)；后面的旧状态只代表历史，不再作为当前任务结论。

## 现行设计概览

- **产品目标：** 从银河全景进入太阳系，再飞近太阳、行星和代表性卫星，科普介绍与轨道/时间数据采用演示缩放。
- **技术基础：** Three.js 负责场景与 GPU 渲染；GSAP 负责镜头过渡；Vite 打包，原生 JavaScript 更新统一的 UI 状态。
- **交互布局：** T15 v3 四角构图，左上品牌、右上全局操作、左下当前场景、右下资料/天体列表；太阳系和天体近景另显示「天体运动」入口。左侧常驻镜头缩放/复位快捷操作（纯净观赏时收起），无需打开抽屉。所有场景复用同一资料面板。
- **界面图标与选择器：** 采用内置 SVG symbol 统一 24px 线性图标及描边，不依赖远程图标字体；控件保留可访问名称、键盘焦点和状态语义。自由漫游目标与飞行速度共用航行面板，目标按母星分组，桌面双列/手机单列，旧星球缩略图列表不再重复显示。展开菜单由本地 src/ui/flightDropdown.js 提供深色弹层、滚动、选中反馈及键盘操作，使用 ARIA combobox/listbox 语义；更多设置中的「渲染画质」也复用该自绘菜单，增加自动/省电/极致三档的描述、图标及选中勾选。隐藏的原生 select 始终为业务状态与 change 事件的数据源；原生手机菜单中的画质控件保持原实现。真实触摸与读屏兼容仍需实体设备验证。
- **信息层级：** 搜索浮窗保留原输入与目标切换逻辑，结果按太阳与行星/所属母星卫星分组，搜索字段与说明固定，结果独立滚动。更多设置复用原画质选择、轨道线和标签开关及帮助按钮，由布局控制器组合为设置行、指南入口和性能状态区。探索指南按视角、航行、快捷键与触控分组；三个区域使用一致的暗色圆角、控件焦点和细滚动条，手机保持单列与可滚动。
- **数据与纹理：** 太阳、八行星、十三颗代表卫星；天文数值与演示尺寸分离。本地 JPG、选择性 KTX2、程序化材质明确区分真实与示意。
- **纹理资源生命周期（T03，2026-10-23；网络复核 2026-10-26）：** 按焦点与场景排队，最多两路在途请求。JPG/KTX2 先用 Fetch 和 AbortController 下载，离开太阳系时取消排队与在途任务；已解码但取消的结果不再修改材质并即时释放，法线/粗糙度的空闲生成任务随场景暂停和恢复。成功资源在会话中缓存供再次进入太阳系复用；应用销毁时中断剩余任务并释放缓存贴图、Shader 贴图、材质与各档 LOD 几何体。非 BFCache 页面退出及 Vite 热替换接入统一销毁入口，BFCache 恢复则保留场景。KTX2 已开始的本地解析无法中途停止，但迟到结果会丢弃并释放。2026-10-26 受控 HTTP/隔离 Chrome 验证了请求取消、缓存复用及 JPG 404 回退（15/15）；真实 GPU 内存回收和手机网络表现仍待验收。
- **KTX2/ETC2 支持与回退（T04，2026-10-26 复核）：** 运行时仅对天王星、海王星、木卫四优先使用 ETC2/Zstd KTX2；不支持 `WEBGL_compressed_texture_etc` 或 KTX2 下载/解析失败时请求 JPG，再失败保留程序底图。新增 `scripts/t04-ktx2-audit.mjs` 以静态容器读取、受控本地资源响应及 WebGL 上传跟踪验证该策略。WebGL2 可通过 `compressedTexSubImage2D` 上传到预分配存储，因此探针同时记录 Image/SubImage 两类调用。Chrome/SwiftShader 15/15 通过；Intel UHD/D3D11 无 ETC 扩展则直接 JPG。实际物理 GPU 的 ETC2 上传、显存和 FPS 仍待验收。
- **镜头、航行与时间：** 独立聚焦/复位与屏幕左侧快捷镜头工具；太阳系/近景内的运动暂停与倍速仅控制演示轨道，自由漫游单独控制飞行速度且天体公转保持基准速率，银河场景不推进太阳系时钟。日期滑杆/日历入口暂时移除，保留内部绝对模拟时刻及定位方法供未来重做；演示模型不是实际日期的天文星历。
- **响应式与性能：** 手机单/多指、抽屉及横竖屏避障，自动画质、后台暂停；实际 GPU 性能以实体设备为准。
- **开发原则：** 复用同一业务源和 DOM 节点，不引入竞争状态；当前任务进度统一由 [开发计划](development-plan.md) 维护。

## V4 真实科普宇宙科学架构（2026-10-26 规划，T25～T30）

**背景与目标：** 现有 `src/data/celestials.js` 的质量、直径等字段为近似科普数据，`radius`/`orbitRadius`/`orbitSpeed`/`phase` 是便于展示的独立模型。旧 `orbitalMechanics.js` 的椭圆轨道仍服务于演示模式；`createGalaxy.js` 的恒星旋臂与星点仍是程序化示意。**2026-10-27 已接入 T26 NASA/JPL DE441 四天体 UTC 星历和 T27 真实比例双模式；2026-10-28 又完成 T28 简化姿态及 T29 Gaia DR3 筛选样本恒星层代码和隔离浏览器验收**。其他太阳系天体的轨道方向仍使用示意模型；Gaia 实际源编号恒星层与随机银河粒子严格分离。V4 进度以 [唯一任务台账](development-plan.md#v4-真实科普宇宙升级计划2026-10-26) 为准；**T25 已完成，T26～T30 代码与隔离浏览器专项验收完成，T29 数据专项 17/17 已补验，T30 V3 兼容回归 58/58 已补验；不要求科学审核。**

### 分层结构与数据契约

拟采用以下数据流，保留现有 Three.js、GSAP、Vite 和 GitHub Pages 的静态托管方式：

1. **天文资料与离线预处理（T25/T26/T29/T30）：** 在构建阶段获取公开的 NASA/JPL 或 Gaia 等资料，按需要记录来源、日期、坐标单位和支持范围并生成静态资源。来源说明供用户查阅，不需要逐字段科研签核；不得在网页动画帧中直接请求外部星历 API。
2. **科普数据层（T25）：** 已建立 `src/data/science/physicalCatalog.js`，对 22 个天体的五类数值集中建模，字段包括 `scientificValue`、`unit`、`definition`、`referenceCenter`、`status`、`method`、`uncertainty`、`validAt` 及可选来源信息。数值分类为 `educational-approximation` 或 `not-applicable`，没有 `verified` 审核状态和强制签核门禁。`celestials.js` 的质量与 `COMPARISON_FACTS` 共享数值目录；演示半径、动画轨道、粒子与云层仍属于视觉层。

### T29 Gaia DR3 真实恒星目录与银河分层实现（2026-10-28）

- **官方样本与可复现获取：** `scripts/science/generate-gaia-dr3.mjs` 对 ESA 官方 Gaia DR3 TAP 的 `gaiadr3.gaia_source` 发出四条固定 `random_index` 区间 ADQL 查询，筛选 `parallax > 1` mas、`parallax_over_error > 10`、`phot_g_mean_mag < 16`、`ruwe < 1.4`、`bp_rp IS NOT NULL`。下载得到 **2057 条真实记录**。四份原始 CSV 存于 `data/sources/gaia-dr3/2026-10-28/`，SHA-256、原始查询、字段与来源链接留在 `public/data/science/gaia-dr3/v1/manifest.json`。可运行 `npm run gaia:generate` 利用已保存的原始 CSV 重新生成静态目录，`npm run gaia:fetch` 用于重新取得官方数据。
- **分块与坐标契约：** 构建产物按估计距离划分为 0～100 pc（18 条）、100～400 pc（365 条）、400～1000 pc（1674 条）三份 JSON，使用 `src/data/science/gaiaCatalog.js` 按需加载与缓存。Gaia `source_id` 保留为字符串，防止 JavaScript 64 位整数精度损失。ICRS J2016.0 赤经/赤纬转换为 Three.js 的场景轴；高 SNR 正视差仅按 `1000 / parallax(mas)` 得出近似 pc 距离，低质量或无距离数据不造坐标。比例是局部恒星视图的可视化单位，不表示银河旋臂深度或全银河大小。
- **独立渲染与界面：** `src/universe/createGaiaLayer.js` 创建独立的真实来源星点，支持三层按需显示、G 波段亮度上限、距离范围、画质等级裁剪、源编号高亮与镜头定位；BP−RP 颜色与星点大小只表示视觉编码，G 为视星等而非恒星固有光度。`src/core/UniverseApp.js` 保留原程序化银河结构示意，仅在用户进入 Gaia 模式时切换显隐；进入太阳系恢复原场景。`src/ui/gaiaControls.js` 把控制集成到 T31 原有「探索」面板，PC 与手机共享唯一入口，不增加全局控制器或复制天体搜索。
- **版本与范围：** Gaia DR3 数据取样是 `random_index` 区间筛选后的小样本，**不是银河系全体恒星、体积完备样本或恒星空间密度统计**；本版本没有校正自行到其它日期、无法用于精确观测预报。真实星点与程序化银河粒子采用不同坐标/渲染图层。页面使用本站静态文件，动画帧不请求 ESA 网络接口，适合版本化静态部署。
- **本地软件验证：** `npm run build` 通过（Vite 7.3.7、63 模块、主包约 832.84 kB，保留超过 500 kB 的非阻断体积提示）；[T29 隔离 Chrome 14/14](baselines/2026-10-28-T29-browser-audit.json)、[T31 布局 33/33](baselines/2026-10-28-T29-T31-regression-audit.json)、[T15 航行/WebGL 77/77](baselines/2026-10-28-T29-T15-regression.json) 与 [V3 导览/资料 58/58](baselines/2026-10-28-T29-V3-regression.json) 全部通过。自动数据专项 `scripts/audit-t29-gaia.mjs` 已编写，但执行 `npm run audit:t29` 的工具调用被平台安全检查拦截，该次未执行；2026-10-28 已补跑 [T29 数据专项 17/17](baselines/2026-10-28-T29-data-audit.json)，核验原始 CSV 和静态分块哈希、坐标与检索。真实 Android/iOS、读屏、原生 GPU 性能和正式部署仍待验。

### T30 OpenNGC 深空图鉴与三条科普路线（2026-10-28）

- **来源和许可：** 采用 Mattia Verga 的 [OpenNGC](https://github.com/mattiaverga/OpenNGC)，许可 CC BY-SA 4.0。官方 NGC.csv 与 addendum.csv 原文及 [署名说明](../data/sources/openngc/2026-10-28/SOURCE-ATTRIBUTION.md) 保存于 data/sources/openngc/2026-10-28/；scripts/science/generate-openngc.mjs 解析原始位置、类型与 Messier 交叉编号，输出 public/data/science/deep-sky/v1/ 的 manifest、objects 和 routes 三份静态资源。原始和派生文件的 SHA-256、源许可及逐条 NASA 参考距离来源链接均可复核。
- **目录、坐标和距离：** 15 个 Messier/NGC 代表对象分别包括星云及遗迹 6 个、星团 3 个、星系 6 个。OpenNGC 赤经/赤纬为 ICRS J2000.0；src/data/science/deepSkyCatalog.js 使用 T29 的方向转换，将它们映射到固定半径 160 的虚拟天球。**标记都处于同一球面**，NASA/Hubble 的参考距离只在资料中展示，不用于推算未知精度的真实空间坐标。M16 关联 OpenNGC 的 NGC 6611 星团/星云区域，并非创生之柱的独立精密中心。
- **渲染和界面：** src/universe/createDeepSkyLayer.js 将各类对象绘为程序化光点，选定目标后沿真实天空方向移动镜头；图标颜色、尺寸与辉光均没有实体摄影或物理直径含义。三个场景图层（银河结构示意、Gaia 恒星样本、T30 深空方向图）互斥。src/ui/deepSkyControls.js 在 T31 原有“探索”工作区接入唯一入口，支持 M/NGC 编号、中英文检索、类别筛选、近似距离及来源链接；PC/手机继续沿用既有控制器。
- **三条课程：** “气体云与恒星的一生”4 站（M42→M8→M16→M1）；“星团与恒星晚年”5 站（M44→M13→M3→M27→M57）；“星系形态与距离阶梯”6 站（M31→M81→M82→M51→M101→M104）。上一站、下一站、完成、结束和当前资料均可操作；路线表示教学顺序，不是实际星际航线。
- **图像用途和限制：** 网站仅使用原创建的方向定位光点，未嵌入或再分发 NASA 观测影像。逐对象 NASA Hubble Messier 资料链接提供照片、拍摄波段及各图署名。OpenNGC 的角位置与 NASA 参考距离来源不同；所有距离为可能随测量方法变化的近似数值。对象选取并非全天深空统计或完整三维银河宇宙。
- **真实软件验证：** [数据 12/12](baselines/2026-10-28-T30-data-audit.json)、[隔离 Chrome 21/21](baselines/2026-10-28-T30-browser-audit.json)、[T29 Gaia 14/14](baselines/2026-10-28-T30-T29-regression-browser-audit.json)、[T31 布局 33/33](baselines/2026-10-28-T30-T31-regression-audit.json)、[T15 航行/WebGL 77/77](baselines/2026-10-28-T30-T15-regression.json) 均通过。Vite 7.3.7 构建 66 模块成功，主包约 848.56 kB，存在非阻断大包警告。**本轮 V3 回归请求被平台安全检查拦截，未执行**；真实手机、硬件 GPU、读屏与线上部署尚无新验收记录。无需人工科学签核。

**后续补验（2026-10-28）：** 在可访问的本地 Vite 服务和隔离 Chrome/SwiftShader 中运行现有 V3/T24 兼容脚本，取得 [V3 58/58 全通过](baselines/2026-10-28-T30-V3-regression.json)（0 失败、0 错误），覆盖路线、资料、收藏、快照、对比及 PC/手机弹窗边界，另保存 13 张截图。历史「当时未执行」记录维持其时点事实；真实设备、原生 GPU 与部署仍待验。

## V3.0 技术设计与当前实现（2026-10-23）

本节记录 V3 的实现及可选后续，任务状态以 [V3 任务台账](development-plan.md#v30-产品功能计划2026-10-23-草案) 为准。T17～T22 已有代码、隔离 Chrome 验收及视觉截图；T23 后续已实现主动启用的离线浏览与版本化缓存。产品价值聚焦主题学习、理解物理比例、收藏并分享已有天体，正式设备与发布验收仍待补齐。

### 数据、内容与导航

- **T17 内容源：** `src/v3/atlasData.js` 以现有 22 个天体稳定 `id` 关联 NASA Science/Goddard、JPL 分类参考页面；`createAtlasExperience.js` 在资料卡显示出处、来源整理日期和「真实数据/演示缩放」说明。编目覆盖已通过脚本核对 22/22；目前尚未对每项科普数值逐条核实来源，不把整理日期称作逐值审核日期。
- **T18 主题导览：** `src/v3/atlasData.js` 定义 3 条各 6 站路线，`createAtlasExperience.js` 负责开始、前进、后退、跳过、退出与手动操作接管，复用 `UniverseApp.focusBody()` 与 `interruptFocusCamera()`，支持低动效设置。退出时终止镜头飞行；从银河切换到太阳系时会检验导览是否仍有效，防止取消后继续聚焦。
- **T19 轻量个人状态：** `src/v3/localAtlas.js` 将收藏及最近访问保存在浏览器 `localStorage`，最多保留 12 条最近访问，支持清除且无账号上传。合法天体直达链接使用 `?scene=planet&body=earth` 等参数，保留 GitHub Pages 的子路径；非法标识回退默认银河并清理查询参数。隔离 Chrome 已验证刷新持久化与非法链接防护。

### 可视化、导出与性能

- **T20 同尺度比较：** `diameterRatio()` 使用 T11 的物理直径数值，在原有比较弹窗绘制同比例 SVG 圆，并在极端直径比下显示明确说明；不人为增加小圆半径。隔离 Chrome 已验证常见与极端比例。
- **T21 轨道图层：** `getAtlasFacts()` 读取母星关系、物理平均距离/公转周期和当前场景模型倾角，在资料卡新增可开关的解释面板；椭圆绘图是通用示意，并非天文轨迹或精确星历。T14 日期定位 UI 仍暂停；移动端图层遮挡与真实数据校对待验。
- **T22 场景分享：** `UniverseApp.captureScene()` 在有限尺寸的独立 WebGL 帧缓冲中读取像素，以 Canvas2D 添加名称、演示比例及素材出处提示后导出 PNG。`createAtlasExperience.js` 优先 Web Share，失败时下载文件，另有 T19 链接复制入口。隔离 Chrome 已成功生成 PNG；手机原生分享/保存尚未实测。
- **T23 可选离线：** 用户主动开启后，`src/offline/offlineManager.js` 注册同源、同路径的 Service Worker。`scripts/generate-offline.mjs` 在 Vite 生产构建后根据实际 JS/CSS、网页、图标与 manifest 内容生成 SHA-256 版本号及 `dist/service-worker.js`；安装时原子缓存基础页面和 JS/CSS（当前 6 个核心资源），升级后删除旧版本的 COSMOS 专用缓存。`src/offline/service-worker-template.js` 采用导航优先联网、离线回退缓存首页的策略，支持离线打开合法的天体直达链接；本地 JPG/KTX2 仅在访问成功后写入缓存，限制最多 12 个、总大小 8 MiB，其他跨域和非 GET 请求不缓存。关闭时注销 Service Worker 并删除 COSMOS 专用缓存；设置区也可单独清除贴图缓存。默认不注册且开发模式禁用，生产 HTTPS 或 localhost 才可启用。`public/manifest.webmanifest` 用相对 URL 适配 GitHub Pages 子路径。2026-10-23 隔离 Chrome 13/13 通过，包括升级淘汰、断网深链、清理和注销，真实 Android/iOS、容量配额及正式站点发布仍待验证。

## 1. 项目定位与当前结论

目标是制作可交互、科普性质的沉浸式 3D 宇宙：从银河全景进入太阳系，查看太阳和八大行星的运动，飞近任一天体，查看数据，探索卫星，并在桌面与手机端操作。天体的尺寸、轨道半径和运动速度采用**展示性缩放**，不作为精确天文历表。

**当前判断：初始方案核心游览链路具备实现代码，升级方案主要交互模块也已落地。T01～T14 的功能代码均已开发，包括质量数据、近景法线、按需加载、KTX2 压缩、动态星云、手机触控、动态画质、自由航行与防穿越、独立视角重置、扩充土星卫星、参数对比口径、球形遮挡投影、大气边缘、木星云带、弹窗/读屏辅助与 WebGL 中断恢复，以及 T14 日期时间轴和指定日期定位。当前支持太阳、八大行星和十三颗代表性卫星（共 22 个天体）。T05～T14 的视觉、交互及设备验收仍待补充，T04 的 GPU 压缩上传/回退亦待验证。计划编号 T01～T14 的功能开发已覆盖；后续为真实浏览器及设备验收、性能基准与发现问题后的修复。**

### V2 视觉要求进一步区分

- **地球昼夜**：有受太阳方向影响的夜侧灯光着色器；是视觉模拟，非真实地球昼夜历算。
- **云层与大气**：有程序化云层、云层自转和大气边缘辉光；T12 叠加晨昏线暖色与方向相关的散射近似，低档继续使用简单边缘效果，尚非物理大气散射。
- **木星云带、土星环**：木星 JPG/程序底图保留，T12 在 Shader UV 上叠加按纬度变化的缓慢漂移；土星环保持几何与着色。动态云带并非真实大气流体模拟。
- **行星阴影**：T12 在球形天体表面着色中近似计算太阳光被一到两颗其他球形天体遮挡的阴影；低画质关闭，环境光保留。2026-10-22 将移动遮挡体改为逐帧采样，避免分帧更新造成投影跳动；同时限制为母星、卫星及同母星卫星之间的遮挡，减少展示比例造成的水星/金星对地球的大块异常暗影。卫星投影半径缩小，半影及直射光衰减减弱；地球云层不再叠加第二层投影，保留云层自然受光和表面阴影。未包含真实太阳视盘影锥、环影与精密食现象预测。
- **几何 LOD 稳定性**：2026-10-22 对球体几何精度切换增加进入/退出滞回阈值，降低镜头阻尼与公转使投影尺寸在临界值附近往返时的网格跳变；保留原有高、中、低分档和资源加载机制。
- **银河空间层次**：星点在三维空间分布；T05 为半透明星云精灵增加缓慢形变，并对尘埃粒子使用 GPU 位移动画。其效果是表现性近似，不是流体模拟。
- **固态天体表面细节（T02）**：地球、月球、火星的 `normalMap` 由已有色彩图估算高度梯度生成，上限 768×384；地球同时按海陆色差估算 `roughnessMap`。保留原始本地 JPG 与程序化回退，**不表示增加了 NASA/USGS 的真实地形高程图**。

太阳、八大行星、公转轨道

**行星近距离探索**

地球云层、大气辉光、昼夜变化

**深空探索**

星云、星际尘埃、宇宙背景

## 部署机制

项目使用 Vite 构建，GitHub Pages 需要发布构建后的 `dist/`，而不是直接将 `main` 分支的源码目录作为静态站点。

仓库中的 `.github/workflows/deploy.yml` 在向 `main` 推送时自动触发，也可在 GitHub Actions 中手动触发：

1. 检出仓库代码并配置 Node.js 22。
2. 执行 `npm ci` 安装锁文件中固定的依赖。
3. 设置 `GITHUB_PAGES=true` 并运行 `npm run build`。
4. 上传 `dist/` 构建产物并通过 GitHub Pages 发布。

## 首次配置

1. 打开 GitHub 仓库 `duanxirui/threejs-universe` 的 **Settings → Pages**。
2. 将 **Build and deployment → Source** 设为 **GitHub Actions**。
3. 推送代码到 `main` 后，进入 **Actions** 页面检查 `Deploy COSMOS ATLAS to GitHub Pages` 工作流的执行结果。
4. 工作流成功并完成 Pages 部署后，通过上方预览地址访问。

## Vite 路径配置

`vite.config.js` 根据环境变量选择构建基础路径：

| 运行模式 | 环境变量 | Vite `base` |
| --- | --- | --- |
| 本地开发与常规构建 | 未设置 `GITHUB_PAGES=true` | `/` |
| GitHub Pages 构建 | `GITHUB_PAGES=true` | `/threejs-universe/` |

Pages 站点托管在仓库子路径 `/threejs-universe/` 下，脚本、样式和行星/卫星贴图必须使用正确的资源路径。工作流已将 Pages 环境变量注入生产构建。

## 本地构建和排查

本地常规构建：

```bash
npm ci
npm run build
npm run preview
```

如果 Pages 页面空白或静态资源 404，按以下顺序排查：

1. 确认 **Settings → Pages** 使用 GitHub Actions，并检查 Actions 中工作流构建与发布的日志。
2. 检查工作流中 `GITHUB_PAGES=true` 是否生效，以及产物是否来自 `dist/`。
3. 查看浏览器开发者工具 Network 面板，检查脚本、CSS、贴图的请求路径是否位于 `/threejs-universe/` 之下。
4. 确认贴图路径已适配 Vite 的 `base`，避免把仓库子路径误写成网站根路径。

这是一份本地部署配置和故障排查指南，不代表已对线上部署结果进行实测。
