# COSMOS ATLAS · 开发方案与技术设计

> 2026-10-21 起，此文件维护设计与架构。当前进度唯一来源为 [任务台账](development-plan.md)；后面的旧状态只代表历史，不再作为当前任务结论。

## 现行设计概览

- **产品目标：** 从银河全景进入太阳系，再飞近太阳、行星和代表性卫星，科普介绍与轨道/时间数据采用演示缩放。
- **技术基础：** Three.js 负责场景与 GPU 渲染；GSAP 负责镜头过渡；Vite 打包，原生 JavaScript 更新统一的 UI 状态。
- **交互布局：** T15 v3 四角构图，左上品牌、右上全局操作、左下当前场景、右下资料/天体列表；太阳系和天体近景另显示「天体运动」入口。左侧常驻镜头缩放/复位快捷操作（纯净观赏时收起），无需打开抽屉。所有场景复用同一资料面板。
- **界面图标与选择器：** 采用内置 SVG symbol 统一 24px 线性图标及描边，不依赖远程图标字体；控件保留可访问名称、键盘焦点和状态语义。自由漫游目标与飞行速度共用航行面板，目标按母星分组，桌面双列/手机单列，旧星球缩略图列表不再重复显示。展开菜单由本地 src/ui/flightDropdown.js 提供深色弹层、滚动、选中反馈及键盘操作，使用 ARIA combobox/listbox 语义；更多设置中的「渲染画质」也复用该自绘菜单，增加自动/省电/极致三档的描述、图标及选中勾选。隐藏的原生 select 始终为业务状态与 change 事件的数据源；原生手机菜单中的画质控件保持原实现。真实触摸与读屏兼容仍需实体设备验证。
- **信息层级：** 搜索浮窗保留原输入与目标切换逻辑，结果按太阳与行星/所属母星卫星分组，搜索字段与说明固定，结果独立滚动。更多设置复用原画质选择、轨道线和标签开关及帮助按钮，由布局控制器组合为设置行、指南入口和性能状态区。探索指南按视角、航行、快捷键与触控分组；三个区域使用一致的暗色圆角、控件焦点和细滚动条，手机保持单列与可滚动。
- **数据与纹理：** 太阳、八行星、十三颗代表卫星；天文数值与演示尺寸分离。本地 JPG、选择性 KTX2、程序化材质明确区分真实与示意。
- **镜头、航行与时间：** 独立聚焦/复位与屏幕左侧快捷镜头工具；太阳系/近景内的运动暂停与倍速仅控制演示轨道，自由漫游单独控制飞行速度且天体公转保持基准速率，银河场景不推进太阳系时钟。日期滑杆/日历入口暂时移除，保留内部绝对模拟时刻及定位方法供未来重做；演示模型不是实际日期的天文星历。
- **响应式与性能：** 手机单/多指、抽屉及横竖屏避障，自动画质、后台暂停；实际 GPU 性能以实体设备为准。
- **开发原则：** 复用同一业务源和 DOM 节点，不引入竞争状态；当前任务进度统一由 [开发计划](development-plan.md) 维护。

## 1. 项目定位与当前结论

目标是制作可交互、科普性质的沉浸式 3D 宇宙：从银河全景进入太阳系，查看太阳和八大行星的运动，飞近任一天体，查看数据，探索卫星，并在桌面与手机端操作。天体的尺寸、轨道半径和运动速度采用**展示性缩放**，不作为精确天文历表。

**当前判断：初始方案核心游览链路具备实现代码，升级方案主要交互模块也已落地。T01～T14 的功能代码均已开发，包括质量数据、近景法线、按需加载、KTX2 压缩、动态星云、手机触控、动态画质、自由航行与防穿越、独立视角重置、扩充土星卫星、参数对比口径、球形遮挡投影、大气边缘、木星云带、弹窗/读屏辅助与 WebGL 中断恢复，以及 T14 日期时间轴和指定日期定位。当前支持太阳、八大行星和十三颗代表性卫星（共 22 个天体）。T05～T14 的视觉、交互及设备验收仍待补充，T04 的 GPU 压缩上传/回退亦待验证。计划编号 T01～T14 的功能开发已覆盖；后续为真实浏览器及设备验收、性能基准与发现问题后的修复。**

**后续 UI 改版 T15（2026-10-20，参考图方案 v3 为当前目标）**：用户提供 CAR ATELIER 3D 展厅截图，要求借鉴其“中央主视觉、四角轻量功能”的整体构图。页面现已调整为左上品牌、右上搜索/纯净/全屏/设置、左下当前场景编号、右下天体资料/视角与时间/天体列表，银河及近景占据中央，无常驻大介绍和整排控制面板；场景切换、卫星、日期和航行功能仍在右下工作区。此前 v2 左侧场景轨道设计保留在历史方案中，以 v3 为准。详见 [T15：四角布局、纯净与全屏实施记录](plans/2026-10-20.md#t15) 和 [10 张改造后截图](baselines/2026-10-20-T15-stage2/README.md)。**第0～2阶段完成主要代码及截图对照；纯净模式已验证，Fullscreen API 请求和失败提示已接入，但真实全屏成功、自由航行/卫星和手机全链路验收仍待进行。**

这里的状态含义：

- **✅ 已实现**：能在源码中定位到对应的数据结构和实现逻辑；不等于本次重新跑过。
- **🟡 部分实现**：已有基础功能，但与原方案的某项要求仍有差距。
- **❌ 未实现**：没有找到对应实现，或只存在替代功能而缺少明确要求的能力。
- **🔍 待验收**：源码已实现，实际设备、交互稳定性或性能目标缺少本次测试证据。

**版本比较限制**：仓库最早可见提交已经包含 V2 文件，无法还原一份独立的 V1 源码快照。本报告比较的是“V1 原始需求 + V2 新增需求”与“当前项目源码”的覆盖关系，**不是 V1 与 V2 两份代码的 Git 差异**。

### V2 视觉要求进一步区分

- **地球昼夜**：有受太阳方向影响的夜侧灯光着色器；是视觉模拟，非真实地球昼夜历算。
- **云层与大气**：有程序化云层、云层自转和大气边缘辉光；T12 叠加晨昏线暖色与方向相关的散射近似，低档继续使用简单边缘效果，尚非物理大气散射。
- **木星云带、土星环**：木星 JPG/程序底图保留，T12 在 Shader UV 上叠加按纬度变化的缓慢漂移；土星环保持几何与着色。动态云带并非真实大气流体模拟。
- **行星阴影**：T12 在球形天体表面着色中近似计算太阳光被一到两颗其他球形天体遮挡的阴影；低画质关闭，环境光保留。2026-10-22 将移动遮挡体改为逐帧采样，避免分帧更新造成投影跳动；同时限制为母星、卫星及同母星卫星之间的遮挡，减少展示比例造成的水星/金星对地球的大块异常暗影。卫星投影半径缩小，半影及直射光衰减减弱；地球云层不再叠加第二层投影，保留云层自然受光和表面阴影。未包含真实太阳视盘影锥、环影与精密食现象预测。
- **几何 LOD 稳定性**：2026-10-22 对球体几何精度切换增加进入/退出滞回阈值，降低镜头阻尼与公转使投影尺寸在临界值附近往返时的网格跳变；保留原有高、中、低分档和资源加载机制。
- **银河空间层次**：星点在三维空间分布；T05 为半透明星云精灵增加缓慢形变，并对尘埃粒子使用 GPU 位移动画。其效果是表现性近似，不是流体模拟。
- **固态天体表面细节（T02）**：地球、月球、火星的 `normalMap` 由已有色彩图估算高度梯度生成，上限 768×384；地球同时按海陆色差估算 `roughnessMap`。保留原始本地 JPG 与程序化回退，**不表示增加了 NASA/USGS 的真实地形高程图**。

## 部署机制

项目使用 Vite 构建，GitHub Pages 需要发布构建后的 `dist/`，而不是直接将 `main` 分支的源码目录作为静态站点。

仓库中的 `.github/workflows/deploy.yml` 在向 `main` 推送时自动触发，也可在 GitHub Actions 中手动触发：

1. 检出仓库代码并配置 Node.js 22。
2. 执行 `npm ci` 安装锁文件中固定的依赖。
3. 设置 `GITHUB_PAGES=true` 并运行 `npm run build`。
4. 上传 `dist/` 构建产物并通过 GitHub Pages 发布。

## 首次配置

1. 打开 GitHub 仓库 `duanxirui/threejs-universe` 的 **Settings → Pages**。
2. 将 **Build and deployment → Source** 设为 **GitHub Actions**。
3. 推送代码到 `main` 后，进入 **Actions** 页面检查 `Deploy COSMOS ATLAS to GitHub Pages` 工作流的执行结果。
4. 工作流成功并完成 Pages 部署后，通过上方预览地址访问。

## Vite 路径配置

`vite.config.js` 根据环境变量选择构建基础路径：

| 运行模式 | 环境变量 | Vite `base` |
| --- | --- | --- |
| 本地开发与常规构建 | 未设置 `GITHUB_PAGES=true` | `/` |
| GitHub Pages 构建 | `GITHUB_PAGES=true` | `/threejs-universe/` |

Pages 站点托管在仓库子路径 `/threejs-universe/` 下，脚本、样式和行星/卫星贴图必须使用正确的资源路径。工作流已将 Pages 环境变量注入生产构建。

## 本地构建和排查

本地常规构建：

```bash
npm ci
npm run build
npm run preview
```

如果 Pages 页面空白或静态资源 404，按以下顺序排查：

1. 确认 **Settings → Pages** 使用 GitHub Actions，并检查 Actions 中工作流构建与发布的日志。
2. 检查工作流中 `GITHUB_PAGES=true` 是否生效，以及产物是否来自 `dist/`。
3. 查看浏览器开发者工具 Network 面板，检查脚本、CSS、贴图的请求路径是否位于 `/threejs-universe/` 之下。
4. 确认贴图路径已适配 Vite 的 `base`，避免把仓库子路径误写成网站根路径。

这是一份本地部署配置和故障排查指南，不代表已对线上部署结果进行实测。
